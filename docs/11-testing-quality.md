# 11 — Testing & Quality

`rv` mutates a user's home directory, decrypts secrets, and installs packages. The test suite is
the reason it is safe to run. This document sets the strategy and the gates.

---

## 1. Strategy

| Layer | What it covers | Speed |
|-------|----------------|-------|
| **Unit** | Pure logic: interpolation, validation, profile resolution, checksums, scrubbing | milliseconds |
| **Filesystem** | Transaction, atomic write, rollback, handlers — against `t.TempDir()` | fast |
| **Fake-runner** | Providers, plugins, subprocess paths — no real package managers | fast |
| **Interop** | Reading and writing artifacts produced by the Python implementation | fast |
| **Integration** | Full lifecycle in a container: init → restore → status → backup → recover | slow, CI only |

Target: **>90% coverage on `internal/`**, matching the Python project's gate. Coverage is a floor,
not a goal — the phase acceptance criteria in [10-build-plan.md](10-build-plan.md) are the real
specification of what must be tested.

---

## 2. Design for testability

Four injection points, all decided in [09-go-architecture.md](09-go-architecture.md) §7. They exist
so that tests need no global state, no serialization, and no real system:

```go
type Env struct {
    Paths  paths.Config      // every runtime path, rooted at t.TempDir() in tests
    Runner providers.Runner  // fake in tests: canned outputs, recorded commands
    Clock  func() time.Time  // fixed in tests
    Out    io.Writer         // a buffer in tests
}
```

The Python suite must run serially because `ProcessLock` uses a fixed path in the real home
directory. **The Go suite MUST NOT inherit that constraint.** With `paths.Config` injected, every
test gets its own lock file and every test can run in parallel:

```go
func TestRestore(t *testing.T) {
    t.Parallel()
    env := testenv.New(t)      // paths rooted at t.TempDir(), fake runner, fixed clock
    ...
}
```

## 4. What must be tested

### Non-negotiable — the safety-critical paths

These get exhaustive coverage. A bug here destroys user data.

1. **Rollback fidelity.** For every mutation shape (create file, modify file, replace symlink,
   replace directory, delete), a failed transaction MUST leave the filesystem byte-identical to its
   pre-state. Compare a recursive hash of the tree before and after.
2. **Atomic write.** No partial file is ever observable at the target path. The temp file lives in
   the target's directory.
3. **Process lock.** Mutual exclusion holds; a second acquirer fails immediately; the lock is
   released on panic.
4. **Permission enforcement.** A secret is never written with group or world bits, at any point in
   its lifecycle — verify the mode immediately after the write, not just at the end.
5. **Scrubbing.** No log line, no error message, no diff output ever contains a registered secret.
   Add a test that runs a full restore with a known secret value and greps the entire captured
   output plus the audit log for it.
6. **Interpolation strictness.** An unset variable never yields an empty path segment.
7. **Path traversal.** A `source` escaping the repo is rejected at load, and no later code path
   accepts one.
8. **Planning has no side effects.** Give an asset a hook that creates a marker file; plan the
   asset (including under `--dry-run`) and assert the marker does not exist. This one test is what
   keeps parallel planning and dry-run safe, and it is trivially easy to regress.
9. **Template strictness.** `missingkey=error` is set; an undefined variable errors rather than
   rendering empty. Assert on a fixture whose template references a variable no context provides.

### Interop tests

| Test | Gate |
|------|------|
| Decrypt a `.age` file produced by the Python build | Phase 4 |
| Encrypt a file, decrypt it with the Python build | Phase 4 |
| Read and roll back a Python-written journal | Phase 5 |
| Read a Python-written `manifest.lock`, rewrite it, compare semantically | Phase 8 |
| Full handover: Python restores, Go reports in-sync and no-ops | Phase 14 |

### Table-driven where the shape repeats

Validation, interpolation, profile resolution, status classification, and provider behavior are all
naturally table-driven:

```go
tests := []struct{
    name string
    yaml string
    wantErr error
}{
    {"unsupported version", "version: 3", manifest.ErrUnsupportedSchemaVersion},
    {"absolute source", "...", manifest.ErrInvalidSource},
    {"world-readable secret", "...", manifest.ErrInsecureSecretPermissions},
}
```

Assert with `errors.Is`, never on message text.

## 5. Integration tests

Behind a build tag, run in CI only:

```go
//go:build integration
```

Full lifecycle across distributions, mirroring the Python project's Dockerfiles
(`reference/tests/integration/`): Ubuntu (apt), Arch (pacman), Alpine (neither — availability
handling).

```
rv init
  → write a manifest with a symlink asset, a template, and an encrypted secret
rv doctor                  → healthy
rv restore base            → files placed, modes correct
rv status -p base          → in_sync
edit a target by hand
rv status -p base          → modified
rv diff -p base            → shows the edit
rv backup base             → repo updated
rv restore base            → no-op
kill -9 mid-restore
rv recover --auto          → pre-state restored
```

Package installation is exercised with a tiny, fast, universally available package (`jq`), or with
the fake runner in unit tests. Do not install heavyweight packages in CI.

## 6. Property-based tests

Three places where properties beat examples:

1. **Interpolation round trip.** For any environment map and any template of `${VAR}` references
   drawn from it, interpolation succeeds and the output contains no `${`.
2. **Profile resolution.** For any randomly generated acyclic `extends` graph, resolution terminates
   and every reachable profile's assets appear. For any graph containing a cycle, it errors.
3. **Rollback.** For a random sequence of planned operations against a random initial tree, an
   induced failure at a random point restores the tree hash exactly.

Use `testing/quick` or `github.com/leanovate/gopter`.

## 7. Static analysis and CI

```yaml
# every push and PR
- go vet ./...
- golangci-lint run           # errcheck, staticcheck, gosec, revive, ineffassign, misspell
- go test -race -cover ./...
- go test -tags=integration ./...        # on main and on release tags
- govulncheck ./...
```

`golangci-lint` configuration requirements:
- `gosec` enabled, with **no blanket suppressions**. Every `#nosec` needs a comment naming the
  reason. (The Python project ignores a broad set of bandit rules globally in `pyproject.toml` —
  do not carry that habit over.)
- `errcheck` enabled. An ignored error must be explicitly assigned to `_` with a comment.
- Cyclomatic complexity capped; the Python `restore()` function is ~300 lines and would fail such a
  gate. Split the engine's steps into named functions from the start.

Coverage gate: **fail CI below 90% on `internal/`**.

## 8. Benchmarks

Track these; they are the payoff for the rewrite:

```go
func BenchmarkManifestLoad(b *testing.B)       // vs. Python's import + parse
func BenchmarkProfileResolve(b *testing.B)     // deep extends chain
func BenchmarkDirectoryChecksum(b *testing.B)  // large asset directory
func BenchmarkPlanParallel(b *testing.B)       // 100 assets
```

Also measure end-to-end startup: `rv --version` wall time. Python pays interpreter startup plus
import cost on every invocation; a Go binary should be an order of magnitude faster. Publish the
number in the migration guide — it is the most legible user-facing benefit.

## 9. Manual test checklist (pre-release)

Automation cannot cover these; run them by hand before tagging:

- [ ] Fresh machine: `rv clone <repo> --restore base` produces a working environment.
- [ ] Interactive conflict prompt appears, and declining leaves the file untouched.
- [ ] `--headless` in a real CI job never blocks on input.
- [ ] Ctrl-C mid-restore leaves a recoverable journal, and `rv recover` restores cleanly.
- [ ] A secret lands with mode `0600` and its plaintext appears nowhere in `~/.local/share/rv/audit.log`.
- [ ] `rv watch` picks up an editor's save (editors often write-and-rename rather than write in place
      — verify the watcher sees it).
- [ ] Shell completion works in bash, zsh, and fish.
- [ ] A machine override file changes behavior on the matching hostname only.

## 10. What not to test

- The standard library.
- `filippo.io/age`'s cryptography — test *your* integration, not its correctness.
- Real package installation in unit tests — that is the fake runner's job.
- Terminal formatting details. Test the data returned by business logic; keep golden-file tests for
  rendering to a minimum, since they break on every cosmetic change and teach nothing.

**Do not port `test_coverage_booster.py`.** The Python project keeps a file whose purpose is to
execute uncovered lines to inflate the coverage number. That is not a test; it converts the coverage
gate into decoration. If a line is hard to cover, either make it testable or delete it.
